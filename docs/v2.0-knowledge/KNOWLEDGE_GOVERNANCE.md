# V2.0 Knowledge Governance

## Publication rule

Only an independently governed publisher may mark a real business entry `approved`. This repository has no such real entries. Adding one requires a stable ID, content review, source reference, version, date, kind, tags, and an intentional scope decision. The runtime does not provide customer-facing write, edit, shell, or knowledge-update tools.

## Change and rollback rule

Create a new version when approved content changes; retain the source reference that supports it. Mark an entry `retired` to remove it from admission. A mistake in scope or status must be corrected at the governed source and verified with the repository tests/eval before release. Runtime audit records the actual version used, so a response can be traced to the exact entry version.

## Safety separation

This general knowledge contract does not make synthetic fixtures professional safety guidance. V1/V1.1/V1.2 safety policy remains authoritative: missing or partial professional safety evidence pauses and escalates to a qualified human. V2.0's controlled fixtures are non-production test material only.
